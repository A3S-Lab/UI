# v0.1.0 Built-in Fields

The stable release includes 10 foundational fields. JSON Schema defines value types and validation, while the UI node selects a control through `widget`. Every example uses the real `FormRenderer`; the JSON beneath it is the controlled value returned by the control.

## Common properties

| Property | Type | Description |
| --- | --- | --- |
| `id` | `string` | Field identifier unique within the form document |
| `kind` | `"field"` | Fixed value for a field node |
| `schemaPath` | JSON Pointer | Points to the field's Schema |
| `widget` | `string` | Built-in control name; defaults to `text` when omitted |
| `label` | `string` | Visible title and accessible name |
| `description` | `string` | Additional field guidance |
| `placeholder` | `string` | Input hint for text controls |
| `options` | `UiOption[]` | Static options for select and radio fields |
| `width` | `1 \| 2 \| 3 \| 4 \| 6 \| 12` | Field width in the 12-column layout |

Required state comes from the parent object Schema's `required` array. Constraints such as `minimum`, `maximum`, `minLength`, `maxLength`, and `pattern` belong only in the Schema.

## Number `number`

An empty input returns `null`; a populated input returns a JavaScript `number`.

<FieldDemo widget="number" />

| Schema | `{ type: "number", minimum?, maximum? }` |
| Note | Use a string or custom component for high-precision decimals and very large integers |

## React usage

```tsx
import { assertCompiled } from '@a3s-lab/ui/form/core';
import { FormRenderer } from '@a3s-lab/ui/form/react';
import '@a3s-lab/ui/form/a3s-ui.css';

const plan = assertCompiled(document);

<FormRenderer plan={plan} value={value} onChange={setValue} />;
```

The host retains the complete form value and receives the next value through `onChange`. Field components do not own persistence, permissions, network requests, or business side effects.

See [built-in fields in `next`](/next/en/guide/fields) for the development field set and its complete contracts.
