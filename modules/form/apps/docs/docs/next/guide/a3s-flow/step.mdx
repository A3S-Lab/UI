# 执行步骤

> [!IMPORTANT]
> 本页记录 A3S Flow `0.4.2` 八节点兼容 API，仅用于迁移。新编辑器请使用 [Flow 1.0 DAG 节点契约](/next/guide/workflow-node-embedding)和 `A3SFlowDagNodeConfigurationPanel`。

`flow.step` 执行接入系统已注册的任务，按配置重试并保存结果；模型调用、工具、HTTP 请求、检索和数据访问都可以作为任务接入。

<A3SFlowNodeDemo nodeType="flow.step" />

## 开发者契约

| 契约 | 值 |
| --- | --- |
| 分类 | 任务执行 |
| Runtime binding | `schedule_step` |
| A3S Flow command | `ScheduleStep` |
| 稳定命令 ID | 不可变的图节点 ID |
| A3S Flow 版本 | `0.4.2` |

## 在 MDX 中使用

示例默认将 **全部尝试失败后** 设为 **从失败分支继续**，因此显示 `failed` 和 `error` 端口；改为 **终止并标记失败** 后，这两个端口会隐藏。

```mdx
import { A3SFlowNodeDemo } from '../../../../components/A3SFlowNodeDemo';

```

## 配置属性

| 属性 | 值类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `step_name` | `string` | 是 | `task.run` | 接入系统已注册的任务。 |
| `input` | Flow expression | 是（节点校验要求） | 字段 `input` | 必须是有效的工作流表达式。 |
| `max_attempts` | Integer `1..100` | 是 | `3` | 高级设置；包含首次执行。 |
| `retry_delay_ms` | Integer `0..86400000` | 是 | `0` | 高级设置；步长为 100 ms。 |
| `on_exhausted` | `fail_run \| continue_workflow` | 是 | `fail_run` | 高级设置；控制失败分支端口。 |

## 端口

| 方向 | ID | 标签 | 类型 | 数据类型 | 可用条件 |
| --- | --- | --- | --- | --- | --- |
| 输入 | `in` | 执行 | Control | `FlowControl` | 始终可用 |
| 输入 | `input` | 步骤输入 | Data | `JsonValue` | 始终可用 |
| 输出 | `success` | 完成 | Control | `FlowControl` | 始终可用 |
| 输出 | `result` | 步骤结果 | Data | `JsonValue` | 始终可用 |
| 输出 | `failed` | 失败分支 | Control | `FlowControl` | `on_exhausted = continue_workflow` |
| 输出 | `error` | 失败详情 | Data | `String` | `on_exhausted = continue_workflow` |

## 配置值

```json
{
  "step_name": "records.sync",
  "input": {
    "apiVersion": "a3s.dev/flow-expression/v1",
    "expression": { "op": "field", "path": "input.record" }
  },
  "max_attempts": 4,
  "retry_delay_ms": 1500,
  "on_exhausted": "continue_workflow"
}
```

## 校验与运行时契约

- 表单校验检查任务名称、重试范围和选项值。
- 节点校验检查表达式契约、重试策略和已连接的条件输出端口 ID。
- 只有 `on_exhausted` 为 `continue_workflow` 时，图边才能连接 `failed` 或 `error`。
- 接入系统根据 `step_name` 查找已注册任务，并从不可变图节点 ID 生成稳定命令 ID。
- 恢复执行时使用相同 ID，输入、任务和重试策略必须保持一致。
- `createA3SFlowNodeBuildConfig` 可以追加或覆盖具体任务所需的字段，同时保留这五个核心属性。
