# Development roadmap

The roadmap is ordered by release risk. Runtime correctness and embeddability come before collaboration and publishing services.

## Current `next` baseline

### A3S Flow 1.0 DAG-node configuration

- The primary contract pins A3S Flow `1.0.0` and tested workflow DSL `0.7.0`. Flow owns the lossless DAG, limits, scopes, container invariants, deterministic ordering, and semantic digests.
- The host owns every `node.data.type`, `A3SFlowDagNodeManifest`, property semantics, ports, compilation, credentials, persistence, and execution. Configuration edits retain unknown DAG and presentation fields.
- The built-in registry contains 20 manifests: 18 appear across seven Playground groups, while `iteration-start` and `loop-start` remain internal container nodes. Fourteen manifests bind directly to Flow 1.0 runtime commands.
- Expression and mapping fields share the runtime-neutral `a3s.dev/flow-expression/v1` JSON AST; configuration does not store JavaScript or template snippets.
- The controlled `A3SFlowDagNodeConfigurationPanel` and `A3SFlowDagNodePreview` expose runtime bindings, typed ports, semantic groups, bounded editors, missing-manifest safety, responsive layouts, and `@a3s-lab/ui@0.3.0`.
- The pinned Langflow `1.11.3` catalog remains an import compatibility adapter; the old eight-node `0.4.2` API remains migration-only.
- Focused tests cover DSL compatibility, DAG limits and scopes, container invariants, deterministic ordering and digests, the manifest catalog and registry, lossless configuration merge, runtime bindings and ports, structured widgets, semantic validation, the primary panel, and the 18-node Playground listing. Engine replay and hook-token uniqueness across active non-terminal runs remain runtime and host obligations.

### Runtime integrity

- A3S Form Schema Profile 1 and native Rust/WASM value evaluation are implemented.
- Computed rules, row-scoped rules, cancellable host validation, data-source dependencies, caching, search, pagination, and failure states are implemented.
- React, Vue, and Web Component adapters use controlled values and host-owned capabilities.
- Runtime locale catalogs and 100, 500, and 1,000-node performance budgets are enforced.

### Complex forms and Studio

- Nested object repeaters and stable row identity are implemented.
- Data grids support dialog editing, sorting, filtering, selection, bounded TSV append, fill-down, and measured virtualization.
- Branched wizards support page validation, review, error recovery, and digest-bound checkpoints.
- The built-in field catalog, matrix fields, file upload, and signature extensions include live MDX examples and property tables.
- The Designer uses A3S UI task panes, tabs, accordions, fields, inputs, item groups, badges, buttons, and tables.

## Before the next package release

- Finish Firefox and WebKit browser evidence for the A3S Flow DAG-node catalog and panel.
- Complete the WCAG 2.2 AA audit for configuration panels, data grids, matrices, and wizards.
- Verify package compatibility and publish the migration notes.
- Publish the package only after the full lint, type, coverage, build, performance, embedding, CLI, Playground, and documentation checks pass.

## Later milestones

### v0.4 — lifecycle and governance

- Mutable drafts and immutable releases;
- history, structured diff, restore, rollback, and environment promotion;
- approval hooks, audit events, policy decisions, and registry version pinning;
- host-neutral presence, locking, patch rebasing, conflict review, and offline synchronization contracts.

### v1.0 — stable production contracts

- Stable document, plan, patch, interaction, and release protocols;
- compatibility decisions and migration tooling for every protocol change;
- policy-bound inspect, propose, diff, simulate, validate, test, approve, and publish operations;
- reference lifecycle and durable human-task integrations.

## Boundaries

Form documents do not execute arbitrary JavaScript. Form Core does not own identity, credentials, persistence, submissions, files, payments, analytics, or external side effects. Hosts provide those capabilities through typed adapters and registries.

The complete acceptance criteria and release gates are maintained in [`ROADMAP.md`](https://github.com/A3S-Lab/UI/blob/main/modules/form/ROADMAP.md).
