# Documentation versions

Published interfaces and in-development capabilities are maintained in separate documentation versions. The version selector switches the complete documentation set, and the language selector switches between Chinese and English.

<VersionTable />

Stable documentation covers published integrations, production compatibility, and pre-upgrade reference. Development documentation covers unreleased capabilities under trial and review.

A capability in `next` enters a new stable version only after passing code, test, documentation, Playground, and compatibility checks. Development documentation does not establish a release commitment.

The version list is maintained in `apps/docs/versions.json`. The build checks every version directory, home page, locale counterpart, and navigation metadata file.

## Default language

Chinese is the default language. Page metadata, navigation, search, and live component examples follow the selected locale in every version.

## Link rules

- Stable English documentation uses root-language paths such as `/en/guide/`.
- Development English documentation retains both prefixes, such as `/next/en/guide/fields`.
- Production integrations should use stable-version links.
- Reviews of unreleased capabilities should retain the explicit `/next/` prefix.
