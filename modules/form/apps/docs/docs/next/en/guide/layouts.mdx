# Layouts and supporting content

Layout nodes organize the interface without changing the controlled value structure. Fields continue to bind data through `schemaPath`, while containers use `children` to define order and nesting. Every example uses the real `FormRenderer` and the A3S UI style entry point.

## Common container properties

| Property | Type | Required | Description |
| --- | --- | --- | --- |
| `id` | `string` | Yes | Stable identifier unique within the document |
| `kind` | `"group" \| "section"` | Yes | Plain container or semantic section |
| `layout` | `UiLayout` | Yes | Arrangement used by the container |
| `children` | `string[]` | Yes | Direct children rendered in array order |
| `label` | `string` | No | Container title; tabs, collapse panels, and wizard pages use it as their navigation label |
| `description` | `string` | No | Supporting guidance below the container title |
| `columns` | `1 \| 2 \| 3 \| 4 \| 6 \| 12` | No | Internal grid columns; defaults to `12` |
| `width` | `1–12` | No | Width occupied by this container in its parent's 12-column grid |
| `gap` | `0 \| 8 \| 12 \| 16 \| 24 \| 32` | No | Space between children in CSS pixels |

Narrow containers collapse side-by-side fields and column groups into one column. Responsive behavior uses the Form container width, not the browser viewport, so the same layout works in a sidebar, dialog, or workspace node.

## Grid container `grid`

Use a grid container for parameter panels where fields need different widths. Each child's `width` determines its span, and `columns` defines the internal grid width.

<LayoutDemo example="grid" />

| Property | Recommended value | Purpose |
| --- | --- | --- |
| `kind` | `"group"` | Creates a layout container without extra business semantics |
| `layout` | `"grid"` | Enables explicit grid placement |
| `columns` | `12` | Aligns with the 12-column field `width` contract |
| `gap` | `12` or `16` | Controls row and column spacing |
| Child `width` | `1–12` | For example, `8 + 4` or `6 + 6` |

```ts
{
  id: 'runtime-grid',
  kind: 'group',
  layout: 'grid',
  columns: 12,
  gap: 16,
  children: ['model', 'timeout'],
}
```

## Two-column layout `columns-2`

`columns-2` is a Designer preset. It creates an outer `layout: "columns"` container and two inner groups with `width: 6`. Each column can contain fields, cards, or other layouts.

<LayoutDemo example="columns-2" />

| Node | Key properties | Purpose |
| --- | --- | --- |
| Outer container | `layout: "columns"`, `columns: 12` | Manages column order and spacing |
| Left column | `kind: "group"`, `width: 6` | First drop region |
| Right column | `kind: "group"`, `width: 6` | Second drop region |
| Inner fields | `width: 1–12` | Use the column's own 12-column grid |

Use two columns when two items benefit from direct comparison. Do not force long guidance, addresses, or multiline inputs into a narrow column.

## Three-column layout `columns-3`

`columns-3` is also a Designer preset. Its three inner groups each use `width: 4`. It works well for short values and related parameters, but not for long text or complex composite fields.

<LayoutDemo example="columns-3" />

| Node | Key properties | Purpose |
| --- | --- | --- |
| Outer container | `layout: "columns"`, `columns: 12` | Manages column order and spacing |
| Each column | `kind: "group"`, `width: 4` | Independent drop region |
| Inside each column | `layout: "flow"`, `columns: 12` | Allows independent inner field widths |

In a narrow container, all three columns automatically stack while preserving `children` order.

## Card group `card`

Use cards for a business group with a meaningful title and description. `kind: "section"` provides grouping semantics, and `layout: "card"` uses the A3S UI Card surface.

<LayoutDemo example="card" />

| Property | Recommended value | Purpose |
| --- | --- | --- |
| `kind` | `"section"` | Expresses an independent content group |
| `layout` | `"card"` | Uses the A3S UI Card style |
| `label` | Short title | States the shared purpose of the fields |
| `description` | One sentence | Adds only necessary completion guidance |
| `children` | Fields or layout nodes | Avoids another card layer without useful information |

Do not wrap every field on a page in a card. Use a card only when its title, description, and fields form one complete task.

## Tabs `tabs`

Tabs suit peer settings that do not have to be completed in order. The outer node uses `layout: "tabs"`; every direct child must be a group or section with `layout: "tab"`.

<LayoutDemo example="tabs" />

| Node | Property | Description |
| --- | --- | --- |
| Tab container | `layout: "tabs"` | Manages the active tab without writing to the form value |
| Tab | `layout: "tab"` | Direct child of the tab container |
| Tab name | Child `label` | Visible and accessible tab name |
| Tab content | Child `children` | Fields and layouts rendered in that tab |

The runtime exposes `tablist`, `tab`, and `tabpanel` semantics and supports Left Arrow, Right Arrow, Home, and End. Use a wizard for ordered steps with progressive validation and review; do not simulate steps with tabs.

## Collapse panels `collapse`

Collapse panels suit infrequent or advanced settings. The outer node uses `layout: "collapse"`, and its direct children use `layout: "collapse-panel"`.

<LayoutDemo example="collapse" />

| Node | Property | Description |
| --- | --- | --- |
| Collapse container | `layout: "collapse"` | Manages a collection of expandable content |
| Collapse panel | `layout: "collapse-panel"` | Direct child of the collapse container |
| Panel name | Child `label` | Copy for the native `summary` |
| Panel content | Child `children` | Fields and layout nodes inside the panel |

The runtime uses native `details` and `summary`, leaving keyboard behavior, expanded state, and assistive-technology semantics to the browser. Do not hide required fields in a closed-by-default panel without an error indicator.

## Supporting text `content`

Supporting text uses `kind: "content"` with `presentation: "text"`. It displays static copy without creating a Schema property or writing to the controlled value.

<LayoutDemo example="content" />

| Property | Type | Description |
| --- | --- | --- |
| `kind` | `"content"` | Fixed value for supporting content |
| `presentation` | `"text"` | Plain text presentation |
| `content` | `string` | Text displayed directly |
| `width` | 12-column width | Span in the parent grid |

Supporting text should contain only information needed to complete the form. Dynamic data, rich text, and executable links belong in an approved host component.

## Divider `divider`

A divider separates adjacent content regions. Leave `content` empty for a line, or set it to display a short label in the middle.

<LayoutDemo example="divider" />

| Property | Type | Description |
| --- | --- | --- |
| `kind` | `"content"` | Fixed value for supporting content |
| `presentation` | `"divider"` | Divider presentation |
| `content` | `string` | Optional divider label |
| `width` | 12-column width | Controls divider length |

A divider does not replace structure. Prefer a section or card when the content has a meaningful title.

## Spacer `spacer`

A spacer provides controlled vertical whitespace. It is hidden from assistive technology and creates neither copy nor a form value.

<LayoutDemo example="spacer" />

| Property | Type | Description |
| --- | --- | --- |
| `kind` | `"content"` | Fixed value for supporting content |
| `presentation` | `"spacer"` | Spacer presentation |
| `gap` | `8 \| 12 \| 16 \| 24 \| 32` | Spacer height; defaults to `24` |
| `width` | 12-column width | Span in the parent layout |

Use spacers sparingly where extra breathing room is necessary. Container `gap` should maintain the page's base rhythm.

## A3S UI style entry point

```ts
import '@a3s-lab/ui/form/a3s-ui.css';
```

This entry point loads `@a3s-lab/ui` and the Form layout layer. Fields continue to use A3S UI `input`, `textarea`, `select`, `field`, and `fieldset` contracts, while containers reuse Card, Tabs, and Accordion surfaces and interaction states. If the host already loads A3S UI, use `@a3s-lab/ui/form/styles.css` to avoid installing global styles twice.
