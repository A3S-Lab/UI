# Run Step

> [!IMPORTANT]
> This page documents the eight-node A3S Flow `0.4.2` compatibility API for migration only. New editors should use the [Flow 1.0 DAG-node contract](/next/en/guide/workflow-node-embedding) and `A3SFlowDagNodeConfigurationPanel`.

`flow.step` runs one registered task, applies its retry policy, and saves the result before the workflow continues.

<A3SFlowNodeDemo nodeType="flow.step" />

## Developer contract

| Contract | Value |
| --- | --- |
| Category | Task execution |
| Runtime binding | `schedule_step` |
| A3S Flow command | `ScheduleStep` |
| Stable command ID | Immutable graph node ID |
| A3S Flow version | `0.4.2` |

## Use in MDX

The example starts with **If all attempts fail** set to **Continue from failure branch**, so it shows the `failed` and `error` ports. Choosing **End run as failed** hides both ports.


## Configuration properties

| Property | Value type | Required | Default | Notes |
| --- | --- | --- | --- | --- |
| `step_name` | `string` | Yes | `task.run` | Task registered by the integrating system. |
| `input` | Flow expression | Yes (node validation) | Field `input` | Must be a valid workflow expression. |
| `max_attempts` | Integer `1..100` | Yes | `3` | Advanced setting; includes the first execution. |
| `retry_delay_ms` | Integer `0..86400000` | Yes | `0` | Advanced setting; step size is 100 ms. |
| `on_exhausted` | `fail_run \| continue_workflow` | Yes | `fail_run` | Advanced setting; controls the failure-branch ports. |

## Ports

| Direction | ID | Label | Kind | Types | Availability |
| --- | --- | --- | --- | --- | --- |
| Input | `in` | In | Control | `FlowControl` | Always |
| Input | `input` | Input | Data | `JsonValue` | Always |
| Output | `success` | Success | Control | `FlowControl` | Always |
| Output | `result` | Result | Data | `JsonValue` | Always |
| Output | `failed` | Recoverable failure | Control | `FlowControl` | `on_exhausted = continue_workflow` |
| Output | `error` | Recoverable error | Data | `String` | `on_exhausted = continue_workflow` |

## Configuration value

```json
{
  "step_name": "records.sync",
  "input": {
    "apiVersion": "a3s.dev/flow-expression/v1",
    "expression": { "op": "field", "path": "input.record" }
  },
  "max_attempts": 4,
  "retry_delay_ms": 1500,
  "on_exhausted": "continue_workflow"
}
```

## Validation and runtime contract

- Form validation checks the task name, retry ranges, and option values.
- Node validation checks the expression contract, retry policy, and connected conditional output IDs.
- A graph edge may target `failed` or `error` only while `on_exhausted` is `continue_workflow`.
- The integrating system finds the registered task named by `step_name` and derives the stable command ID from the immutable graph node ID.
- When resuming a saved workflow, the same ID must keep the same input, task, and retry policy.
- `createA3SFlowNodeBuildConfig` can append or override task-specific fields without removing these five core properties.
