# Wait Until

> [!IMPORTANT]
> This page documents the eight-node A3S Flow `0.4.2` compatibility API for migration only. New editors should use the [Flow 1.0 DAG-node contract](/next/en/guide/workflow-node-embedding) and `A3SFlowDagNodeConfigurationPanel`.

`flow.wait` pauses the workflow until an absolute UTC time supplied directly or read from saved workflow state.

## Configuration properties

| Property | Value type | Required | Default | Notes |
| --- | --- | --- | --- | --- |
| `resume_at` | Flow expression | Yes | Field `input.deadline` | Accepts `DateTime`; use an absolute UTC literal or a dynamic field. |

## Ports

| Direction | ID | Label | Kind | Types | Availability |
| --- | --- | --- | --- | --- | --- |
| Input | `in` | In | Control | `FlowControl` | Always |
| Input | `resume_at` | Resume at | Data | `DateTime` | Always |
| Output | `resumed` | Resumed | Control | `FlowControl` | After the deadline |

## Configuration value

```json
{
  "resume_at": {
    "apiVersion": "a3s.dev/flow-expression/v1",
    "expression": { "op": "field", "path": "input.resumeAt" }
  }
}
```

An absolute timestamp can be stored directly in the expression:

```json
{
  "apiVersion": "a3s.dev/flow-expression/v1",
  "expression": { "op": "literal", "value": "2026-08-10T12:30:00Z" }
}
```

## Validation and runtime contract

- Form validation checks the expression object shape.
- Node validation requires a literal to be a valid absolute UTC timestamp ending in `Z`; a dynamic expression must reference at least one field.
- Node-local validation does not prove that a dynamic field comes from workflow input or persisted state, or that its resolved value is a timestamp.
- The host restricts field-path sources and derives the stable command ID from the immutable graph node ID.
- When resuming a saved workflow, the same ID must keep the same deadline.
