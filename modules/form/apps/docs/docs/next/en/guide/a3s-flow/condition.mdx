# Condition

> [!IMPORTANT]
> This page documents the eight-node A3S Flow `0.4.2` compatibility API for migration only. New editors should use the [Flow 1.0 DAG-node contract](/next/en/guide/workflow-node-embedding) and `A3SFlowDagNodeConfigurationPanel`.

`flow.condition` evaluates a side-effect-free condition over workflow data and selects the next execution path.

<A3SFlowNodeDemo nodeType="flow.condition" />

## Developer contract

| Contract | Value |
| --- | --- |
| Category | Control flow |
| Runtime binding | `runtime_condition` |
| A3S Flow version | `0.4.2` |
| Stable command ID | Not applicable |
| Lowering | The integrating system evaluates the condition deterministically when the workflow resumes |

## Use in MDX

Pass the stable node type to embed the condition configuration with both branch ports:

```mdx
import { A3SFlowNodeDemo } from '../../../../../components/A3SFlowNodeDemo';

<A3SFlowNodeDemo nodeType="flow.condition" />
```

## Configuration properties

| Property | Value type | Required | Default | Notes |
| --- | --- | --- | --- | --- |
| `input` | JSON object | No | `{}` | JSON value or upstream data exposed to the predicate. |
| `expression` | Flow expression | Yes | `input.approved == true` | Reads saved workflow state without side effects. |
| `matched_label` | `string` | Yes | `Matched` | Canvas label for the true path. |
| `otherwise_label` | `string` | Yes | `Otherwise` | Canvas label for the false path. |

## Ports

| Direction | ID | Label | Kind | Types | Availability |
| --- | --- | --- | --- | --- | --- |
| Input | `in` | In | Control | `FlowControl` | Always |
| Input | `value` | Value | Data | `JsonValue` | Always |
| Output | `matched` | Matched | Control | `FlowControl` | Predicate returns `true` |
| Output | `otherwise` | Otherwise | Control | `FlowControl` | Predicate returns `false` |

## Configuration value

```json
{
  "input": { "approved": true },
  "expression": {
    "apiVersion": "a3s.dev/flow-expression/v1",
    "expression": {
      "op": "eq",
      "left": { "op": "field", "path": "input.approved" },
      "right": { "op": "literal", "value": true }
    }
  },
  "matched_label": "Approved",
  "otherwise_label": "Needs review"
}
```

## Validation and runtime contract

- Form validation checks labels and JSON property shapes.
- Node validation checks the expression envelope and supported AST operators.
- Node-local validation does not prove that a field path comes from workflow input or persisted history.
- The integrating system or compiler restricts field roots to workflow input or saved state, resolves the input port mapping, and guarantees side-effect-free evaluation.
- Branch labels affect the canvas only; graph edges remain bound to the stable `matched` and `otherwise` port IDs.
