# Hotkey Input

Hotkey Input records one keyboard chord for a command assignment. It keeps the committed shortcut visible, makes recording explicit, and preserves the prior value when replacement is cancelled or rejected.

### Parameters

| Parameter                                          | Value                        | Purpose                                                                                                                                |
| -------------------------------------------------- | ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| Root                                               | `<div class="hotkey-input">` | Owns recording state and the compound field boundary                                                                                   |
| `data-hotkey-value`                                | Canonical chord              | Supplies the initial value and reflects the rendered value; while clearing is still a recording draft, this may be empty before commit |
| Input                                              | Read-only text input         | Preserves focus, form submission, accessible value, and a single keyboard entry point                                                  |
| `aria-describedby`                                 | Feedback element ID          | Associates persistent guidance and visible rejection reasons with the input                                                            |
| `[data-hotkey-preview]`                            | Empty `<span>`               | Receives platform-aware, `aria-hidden` keycaps for the committed chord                                                                 |
| `[data-hotkey-clear]`                              | Named button                 | Begins an empty replacement draft; the controller keeps it out of the default Tab sequence                                             |
| `[data-hotkey-feedback]`                           | Described text element       | Shows idle guidance, modifier-only guidance, and host rejection reasons                                                                |
| `[data-hotkey-status]`                             | Polite live region           | Announces recording, cancellation, clearing, rejection, and the committed value                                                        |
| `data-recording-placeholder`                       | Localized string             | Names the capture action inside the empty recording field                                                                              |
| `data-recording-message` / `data-modifier-message` | Localized strings            | Provide visible recording guidance and modifier-only recovery                                                                          |
| `data-invalid-message`                             | Localized string             | Explains malformed programmatic values containing zero or several base keys                                                            |
| `data-*-announcement`                              | Localized strings            | Localize bounded screen-reader status messages                                                                                         |

### JavaScript API

The controller exposes `getValue()`, `setValue(value, options)`, `clear(options)`, `start(options)`, `stop(options)`, and `refresh()`. `getValue()` always returns the committed chord, including while an empty replacement draft is visible.

Canonical values contain zero or more modifiers in `Control`, `Alt`, `Shift`, `Meta` order and exactly one non-modifier key. Use `Plus` for the literal `+` key. Common API aliases such as `Ctrl` and `Command` are normalized; platform symbols never enter the stored value.

Use `event.detail.reject(message)` to reject duplicate, reserved, or permission-controlled assignments. This preserves the old chord, exits recording, and exposes the reason through both visible feedback and `a3s:hotkey-rejected`.

```js
const input = document.querySelector(".hotkey-input");
const assigned = new Map([["Control+Shift+X", "Command palette"]]);

input.addEventListener("a3s:hotkey-before-change", (event) => {
  const command = assigned.get(event.detail.value);
  if (command) event.detail.reject(`Already assigned to ${command}.`);
});

input.addEventListener("a3s:hotkey-change", (event) => {
  saveShortcut(event.detail.value);
});
```

| Event                         | Detail                                                   | When it fires                                                 |
| ----------------------------- | -------------------------------------------------------- | ------------------------------------------------------------- |
| `a3s:hotkey-before-change`    | `value`, `previousValue`, `source`, `reject(message)`    | Before a chord or clear action commits; cancel or reject here |
| `a3s:hotkey-change`           | `value`, `previousValue`, `source`                       | After an accepted committed value changes                     |
| `a3s:hotkey-rejected`         | `value`, `previousValue`, `source`, `message`            | After validation or the host rejects a candidate              |
| `a3s:hotkey-recording-change` | `recording`, `source`, optional `restored` or `rejected` | When capture starts or ends                                   |

## Product decisions

Use Hotkey Input only for assigning one chord to a named command. Use a regular text field for shortcut search, a keycap for display-only hints, and a command list for browsing several existing assignments. The host owns the command registry, duplicate detection, operating-system reservations, permissions, persistence, and global listener registration.

Some operating-system or browser shortcuts never reach page JavaScript. Do not promise that every chord can be captured, and do not disable platform escape routes to force capture.

## States and variants

- **Ready, populated:** the committed chord appears as platform-aware keycaps, while the normalized input value remains available to forms and assistive technology.
- **Empty:** the clear action is hidden and adjacent guidance explains how to create the first assignment.
- **Recording:** focusing the input or pressing Enter starts one bounded capture transaction. Modifier-only input keeps recording and asks for a base key.
- **Replacing:** the clear action opens an empty draft. Escape or lost window focus restores the committed value; Tab, pointer exit, or an accepted chord commits the draft.
- **Rejected or invalid:** the old committed value remains visible, focus stays on the input, and the specific conflict or format reason appears next to it. Press Enter to retry.
- **Disabled:** the value remains readable, native `disabled` prevents capture, and adjacent text explains the policy or permission constraint.

## React

```tsx
import { HotkeyInput, useHotkeyInput } from "@a3s-lab/ui/react";

export function QuickSearchShortcut({
  onChange,
}: {
  onChange(value: string): void;

  const shortcut = useHotkeyInput({

        onChange((event as CustomEvent<{ value: string }>).detail.value);

  return (

          readOnly
          autoComplete="off"
          inputMode="none"
```

## Accessibility

- Prefer a visible `label`; a placeholder is capture guidance, not the control name.
- The input is the only default Tab stop. Delete or Backspace starts an empty replacement, Enter retries after commit or rejection, Tab leaves the complete control, and Escape cancels the active recording without blurring the input.
- Modifier-only, cancellation, clearing, rejection, and committed values are announced through the bounded polite status region. Visible feedback remains present for people who do not receive live announcements.
- Keycaps are `aria-hidden` because the read-only input already exposes the canonical chord. `aria-keyshortcuts` is intentionally omitted: the saved chord activates the host command, not the recorder itself.
- `KeyboardEvent.key` keeps capture layout-aware. Dead, composing, and unidentified keys do not commit a partial chord; the literal plus key is encoded as `Plus`.
- Window blur and document hiding cancel the active recording so browser switching cannot silently overwrite an assignment. Normal Tab or pointer exit commits an intentional empty replacement draft.
- Native `disabled` is required for an unavailable input. Keep the committed value and an adjacent reason readable instead of relying on opacity or color alone.
