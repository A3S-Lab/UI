# Dock 工作区

Dock 工作区用于需要持续重排上下文、主画布、检查器、预览和输出的专业应用。A3S UI 直接重导出 Dockview 8.1.0 的 MIT API，并提供 A3S 主题、布局持久化以及 React/Vue Hooks；面板内容、权限、数据和窗口策略仍由宿主负责。

<Preview layout="workspace">
  <DockviewDemo mode="dock" />
</Preview>

容器必须拥有可计算的宽高。不要用面板布局替代业务路由；仅保存用户可恢复的视图状态。

`useDockviewLayout` 在布局就绪时恢复版本化快照，恢复失败时创建默认布局，并在变更后防抖保存。它返回 `api`、`status`、`save()`、`restore()`、`clear()` 和 `reset()`。重置时会先移除 Dockview 保留的 Edge Group 槽位，再重建默认布局；原生集成可调用 `resetDockviewLayout(api, initialize)` 获得相同行为。迁移旧快照时传入 `migrate` 与 `validate`；不要把业务数据写进布局快照。

## 关键编排

### Edge、浮动、弹出与最大化

```ts
const explorer = api.addEdgeGroup("left", {
  id: "explorer-edge",
  initialSize: 240,
  collapsedSize: 34,
});
api.addPanel({
  id: "files",
  component: "explorer",
  position: { referenceGroup: explorer.id },
});

api.addFloatingGroup(api.getPanel("inspector"), {
  width: 320,
  height: 440,
  position: { right: 24, top: 56 },
});
await api.addPopoutGroup(api.getPanel("preview"));
api.activePanel?.api.maximize();
api.activePanel?.api.exitMaximized();
```

### 外部拖放与事件

外部资源必须先经过宿主授权，再创建面板。`onWillDrop` 可以拒绝落点，`onDidDrop` 只记录已完成结果。

```tsx
<DockviewReact
  components={components}
  onReady={layout.onReady}
  onWillDrop={(event) => {
    if (!canOpenResource(event)) event.preventDefault();
  }}
  onDidDrop={(event) => auditLayoutDrop(event)}
/>
```

## 许可边界

当前入口只依赖 MIT 版本，不复制商业模块。高级标签溢出、多行标签、固定标签、标签与 Group Chip 上下文菜单、拖放罗盘、智能参考线、自动隐藏 Edge Group、自动停靠到边缘、布局历史、空间键盘导航和键盘停靠不属于本集成。需要这些能力时应直接评估上游商业许可，不能用外观相似的本地实现规避边界。

## 产品与无障碍要求

- 每个面板应有稳定 ID、可理解标题和明确滚动所有者；不要用位置表达唯一语义。
- Popout 可能被浏览器拦截，必须保留原面板并提供重试说明。
- 保存失败不能阻止拖放和调整大小；恢复失败应回到可用默认布局。
- 自定义标签、标题栏动作和面板内容必须保持可见焦点与可访问名称。
- 触控设备需要足够大的标签和操作目标；复杂工作台在窄屏应合并为标签组，而不是压缩成不可读分栏。
