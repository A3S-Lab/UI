# Task Plan

Task Plan exposes a bounded sequence of work without turning internal reasoning into interface copy. The host owns plan creation, step transitions, persistence, and cancellation.

## Usage

```html
<section class="task-plan" data-state="active" aria-labelledby="plan-title">
  <header>
    <h2 id="plan-title">Release plan</h2>
    ...
  </header>
  <ol>
    <li class="plan-step" data-state="complete">...</li>
    <li class="plan-step" data-state="active" aria-current="step">...</li>
  </ol>
  <footer>...</footer>
</section>
```

### Parameters

| API                | Values                                           | Purpose                                                                                  |
| ------------------ | ------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| `data-state`       | `draft`, `active`, `paused`, `complete`, `error` | Plan lifecycle                                                                           |
| `data-variant`     | `plain`                                          | Removes the owning surface so the plan can sit inside an inspector or transcript section |
| Direct `<ol>`      | Required                                         | Ordered plan steps                                                                       |
| `data-plan-status` | Recommended                                      | Visible lifecycle label                                                                  |
| Native progressbar | Optional                                         | Bounded aggregate progress                                                               |

## States and variants

Keep completed work visible and preserve the active step when execution pauses. An error belongs to the affected Plan Step unless the entire plan cannot continue. Use `data-variant="plain"` only when a parent surface already owns the boundary; it removes the Task Plan border and inline padding without changing step semantics.

```html
<section class="task-plan" data-state="active" data-variant="plain">
  <header>
    <h2>Execution plan</h2>
    <span data-plan-status>In progress</span>
  </header>
  <ol>
    <li class="plan-step" data-state="active" aria-current="step">...</li>
  </ol>
</section>
```

## Accessibility

Name the section with a heading. Use `aria-current="step"` once. Progress text must remain available when a visual progressbar is omitted.

## React

```tsx
import { TaskPlan } from "@a3s-lab/ui/react";

export function Example() {
  return (
    <TaskPlan data-state="active" aria-labelledby="plan-title">
      <header>
        <h2 id="plan-title">Release plan</h2>
        <p>2 of 3 steps complete</p>
      </header>
      <ol>
        <li className="plan-step" data-state="complete">
          <strong>Build package</strong>
          <span>Complete</span>
        </li>
        <li className="plan-step" data-state="active" aria-current="step">
          <strong>Verify responsive behavior</strong>
          <span>In progress</span>
        </li>
      </ol>
      <footer>
        <button type="button">Pause plan</button>
      </footer>
    </TaskPlan>
  );
}
```

The adapter replaces only the documented semantic root and adds no wrapper; its children keep the HTML contract shown above.
