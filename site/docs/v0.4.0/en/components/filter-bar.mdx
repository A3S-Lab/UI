# Filter Bar

Filter Bar keeps search, facets, active conditions, result count, and clear actions in one stable region. It maintains control state and emits events while the host application owns result queries.

## Usage

```html
<form class="filter-bar" role="search" aria-label="Filter projects">
  <div data-filter-controls>
    <div data-filter-primary>
      <input
        class="input"
        type="search"
        data-filter-search
        aria-label="Search projects"
      />
      <div data-filter-group data-selection="single">
        <button
          type="button"
          data-filter-toggle
          data-filter-name="state"
          data-filter-value="active"
          aria-pressed="true"
        >
          Active
        </button>
      </div>
    </div>
    <div data-filter-actions>
      <output data-filter-count>12 projects</output
      ><button type="button" data-filter-clear>Clear</button>
    </div>
  </div>
</form>
```

After loading `filter-bar.js`, the controller synchronizes single- or multi-select buttons, active chips, and clear actions.

### Parameters

| API                                       | Purpose                                                                                |
| ----------------------------------------- | -------------------------------------------------------------------------------------- |
| `data-filter-search`                      | Native search input or its compound field container                                    |
| `data-filter-group`                       | Related conditions; `data-selection` is `single` or `multiple`                         |
| `data-required="true"`                    | Keeps one condition active in a single-select group                                    |
| `data-default-value="value"`              | Required-group fallback used by clear and controlled updates                           |
| `data-filter-toggle`                      | Expresses a condition with `data-filter-name`, `data-filter-value`, and `aria-pressed` |
| `data-filter-chip` / `data-filter-remove` | Active condition and its remove action                                                 |
| `data-filter-count`                       | Result count updated by the host                                                       |

### JavaScript API

```js
const filters = document.querySelector(".filter-bar");
filters.setFilters([{ name: "state", value: "active" }]);
filters.setSearch({ query: "release" });
console.log(filters.getState());
filters.resetFilters();
filters.addEventListener("a3s:filter-change", ({ detail }) =>
  updateQuery(detail),
);
```

`getFilters()` and `getSearch()` return query snapshots. `setFilters()`, `setSearch()`, `clear()`, and `resetFilters()` keep segmented controls, active chips, and search values synchronized. Native `form.reset()` uses the same initial snapshot, while `requestSubmit()` keeps normal form submission semantics. `refresh({ preserve, resetInitial })` rebinds replaced controls.

`a3s:filter-before-change` is cancelable and restores the previous query when rejected. `a3s:filter-change` contains `previous`, `current`, `source`, `kind`, and the compatibility `filters` fields. Programmatic search updates emit one native `input` event and one custom change event; user typing reuses its existing native event rather than duplicating it.

## States and variants

Show two to four frequent segmented conditions directly. Put larger facet sets in Select, Combobox, or Dropdown Menu. Do not turn every field into a chip or add a complex toolbar for one condition.

Keep input and active conditions visible while remote results load. No results belongs to the results region's Empty state rather than replacing the Filter Bar.

## Accessibility

Use a named search form. Toggle buttons maintain `aria-pressed`, and result-count changes use polite announcements. Keep focus near a removed condition, and do not move focus into the results after clearing all filters.

## React

```tsx
import { FilterBar, useFilterBar } from "@a3s-lab/ui/react";

export function Example() {
  const control = useFilterBar();
  return (
    <FilterBar ref={control.ref} aria-label="Filter Bar"><label>Name<input name="name" /></label><button type="submit">Continue</button></FilterBar>
  );
}
```

`useFilterBar` subscribes to manifest-declared DOM events and calls only public manifest methods. The adapter creates no second, framework-only state model.
