# A3S Flow 1.0 DAG 节点配置

A3S Form 将 Flow workflow DSL 作为无损 DAG 契约处理。Flow 负责图结构、作用域校验、执行顺序和语义 digest；接入宿主负责每个 `node.data.type`、属性 manifest、节点编译、凭证、持久化和执行。

## 契约基线

| 契约 | 已实现基线 |
| --- | --- |
| A3S Flow 引擎 | `1.0.0` |
| 已测试 workflow DSL | `0.7.0` |
| 主 manifest 目录 | 18 个可见节点和 2 个内部容器起始节点 |
| 运行时命令 | 14 个 Flow 1.0 command binding |
| 组件系统 | `@a3s-lab/ui@0.3.0` |
| Form 兼容标识 | `a3s-flow/1.0.0`、`a3s-flow-workflow-dsl/0.7.0` |

主 Playground 将 18 个可见 manifest 分为 Control flow、Task execution、Wait & callbacks、Run outcome、Run control、Child work 和 Containers。`iteration-start` 与 `loop-start` 由所属容器创建，不显示在插入目录中。

## 所有权边界

| Flow 负责的契约 | 宿主负责的契约 |
| --- | --- |
| 无损 `nodes`、`edges`、作用域和未知展示扩展 | 每个 `data.type` 判别值的含义 |
| 节点与边上限、稳定 ID、引用、无环排序和跨作用域边拒绝 | 属性字段、标签、默认值、端口和宿主专用 manifest |
| Iteration 与 Loop 容器及起始节点约束 | 从 manifest 支持的 DAG 节点编译为 Flow 命令或宿主操作 |
| 排除纯展示字段后的规范执行 digest | Handler registry、凭证、授权、持久化和副作用 |

Form 不会重写未知 DAG 字段。配置编辑只替换所选 manifest 声明的字段，保留 `data.type` 以及全部顶层创作和展示扩展。

## 宿主管理的 manifest

`A3SFlowDagNodeManifest` 是节点配置界面的唯一事实来源。宿主可以使用内置目录，也可以注册产品专用类型，而无需扩展 Flow 引擎协议。

```ts
import {
  createA3SFlowDagNodeRegistry,
  defineA3SFlowDagNodeManifest,
} from '@a3s-lab/ui/form/a3s-flow';

const approvalManifest = defineA3SFlowDagNodeManifest({
  type: 'acme.approval',
  display_name: '审批',
  description: '等待由宿主管理的审批结果。',
  category: 'host',
  categoryLabel: '宿主节点',
  role: 'host',
  ports: {
    inputs: [{ id: 'in', label: '进入', kind: 'control', types: ['FlowControl'] }],
    outputs: [{ id: 'approved', label: '已批准', kind: 'control', types: ['FlowControl'] }],
  },
  input_types: ['FlowState'],
  output_types: ['FlowState'],
  fields: [
    {
      name: 'team',
      display_name: '审核团队',
      type: 'str',
      _input_type: 'StrInput',
      value: 'finance',
      required: true,
    },
  ],
  outputs: [],
});

export const flowNodeRegistry = createA3SFlowDagNodeRegistry([approvalManifest]);
```

创建 registry 时会拒绝重复类型。构造 manifest 时会拒绝空标识、重复字段名、缺少 binding 的 runtime-command 节点，以及缺少起始节点契约的容器。

## React 嵌入

```tsx
import { useState } from 'react';
import {
  createA3SFlowDagNode,
  requireA3SFlowDagNodeManifest,
} from '@a3s-lab/ui/form/a3s-flow';
import {
  A3SFlowDagNodeConfigurationPanel,
  A3SFlowDagNodePreview,
} from '@a3s-lab/ui/form/react';
import '@a3s-lab/ui/form/a3s-ui.css';

const manifest = requireA3SFlowDagNodeManifest('flow.step');

export function StepSettings() {
  const [dagNode, setDagNode] = useState(() =>
    createA3SFlowDagNode('step-fetch-customer', manifest),
  );

  return (
    <div className="node-settings">
      <A3SFlowDagNodePreview dagNode={dagNode} manifest={manifest} />
      <A3SFlowDagNodeConfigurationPanel
        dagNode={dagNode}
        manifest={manifest}
        onChange={setDagNode}
        connectedOutputPortIds={connectedOutputPortIds}
        onApply={(nextNode, document) =>
          saveDagNode({
            node: nextNode,
            formCompatibility: document.metadata.compatibility,
          })
        }
        onRequestConnection={({ valuePath, inputTypes }) =>
          openConnectionPicker({ valuePath, inputTypes })
        }
      />
    </div>
  );
}
```

面板受控且与宿主实现无关。它不会解析图边、保存数据、获取凭证或执行节点。未注册的 manifest 会显示本地化提示，DAG 节点保持不变。表达式、输入 Schema 和批次字段在主路径使用结构化编辑器；适用的核心节点语义校验先于宿主 Form 校验执行，任一失败都会阻止 Apply。

宿主已经加载 A3S UI 时可以改用隔离样式入口：

```ts
import '@a3s-lab/ui/form/styles.css';
import '@a3s-lab/ui/form/a3s-flow.css';
```

## DAG 校验与语义 digest

```ts
import {
  compileA3SFlowWorkflowDag,
  digestA3SFlowWorkflowDag,
  parseA3SFlowWorkflowDslJson,
} from '@a3s-lab/ui/form/a3s-flow';

const parsed = parseA3SFlowWorkflowDslJson(source);
if (!parsed.ok) throw new Error(parsed.issues[0]?.message);

const graph = parsed.document.workflow.graph;
const compilation = compileA3SFlowWorkflowDag(graph);
if (!compilation.ok) throw new Error(compilation.issues[0]?.message);

const executionDigest = digestA3SFlowWorkflowDag(graph);
```

解析器执行 10 MiB 文档上限并给出 DSL 版本兼容性。DAG 编译执行 10,000 节点、100,000 边上限，以及唯一 ID、有效端点与父节点、同作用域边、无环顺序和合法 Iteration/Loop 起始子节点约束。Digest 按 UTF-8 ID 排序节点与边，并移除 viewport、选择、位置、尺寸、动画、样式等纯展示字段。因此修改应用名称或移动节点不会改变执行身份，语义图变化会改变 digest。

## 主面板属性

| 属性 | 类型 | 必填 | 用途 |
| --- | --- | --- | --- |
| `dagNode` | `A3SFlowWorkflowDagNode` | 是 | 由宿主控制的完整无损 DAG 节点 |
| `manifest` | `A3SFlowDagNodeManifest` | 否 | 显式 manifest；省略时由 `registry` 按 `data.type` 解析 |
| `registry` | `A3SFlowDagNodeRegistry` | 否 | 宿主 registry；默认使用内置 Flow 1.0 目录 |
| `onChange` | `(node) => void` | 是 | 接收无损合并 manifest 字段后的节点 |
| `onApply` | `(node, document) => void \| Promise<void>` | 否 | 通过宿主提交当前节点 |
| `onReset` | `(node) => void` | 否 | 观察恢复 manifest 默认值的操作 |
| `connectedOutputPortIds` | `readonly string[]` | 否 | 为条件端口校验提供图上下文 |
| `onRequestConnection` | `(request) => void` | 否 | 打开宿主连接选择器 |
| `hostAdapter` | `FormHostAdapter` | 否 | 解析允许的数据源、校验与操作 |
| `widgetRegistry` | `FormWidgetRegistry` | 否 | 增加或覆盖宿主允许的控件 |
| `locale` | `string` | 否 | 选择运行时文案与格式化规则 |
| `readOnly` | `boolean` | 否 | 禁用重置、编辑、连接与 Apply 操作 |

`A3SFlowDagNodePreview` 接受同一个 `dagNode`、可选 `manifest` 或 `registry`，以及 `selected`、`technical`、`className` 等图展示属性。它渲染 manifest 端口和 runtime binding，但不负责图选择或边状态。

## 迁移兼容

`A3SFlowNodeConfigurationPanel`、`A3SFlowNodePreview`、`A3SFlowCoreNodeDefinition` 与八节点 `0.4.2` 目录仅保留用于迁移。对应的[旧版节点章节](/components/form-system/a3s-flow/start)记录旧的纯配置值契约。新编辑器应保存 `A3SFlowWorkflowDagNode`，并使用 DAG 面板与预览。

固定到 Langflow `1.11.3` 的描述符适配器是独立导入兼容层，不是 Flow 节点目录。参见 [Langflow 兼容性](/components/form-system/langflow-compatibility)。
