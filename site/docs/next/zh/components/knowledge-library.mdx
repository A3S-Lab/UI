## 产品决策

知识库是围绕已批准来源建立的长期命名边界，不是文件夹别名、对话附件列表或装饰性的数据库卡片。

- 每个知识库都应呈现来源数量、新鲜度、索引阶段与恢复路径。
- `queued` 与 `running` 必须分开；等待资源和正在建立索引对应不同预期。
- 更新失败时保留上一版可搜索内容；破坏性重建必须走单独的宿主流程。
- 自动更新策略应说明最小间隔、暂停条件与可见的手动恢复动作。
- 来源选择、认证、解析、切块、嵌入、向量存储、检索质量和访问控制由宿主负责。

`useKnowledgeLibrary` 向 React 和 Vue 暴露同一套控制器方法与 DOM 事件。应用数据仍留在宿主 Store 中，hook 不会复制索引状态。

## 控制器契约

| 区域 | 契约 |
| --- | --- |
| 根元素 | `.knowledge-library`，推荐使用 `<section>` |
| 布局 | 默认保留导航并以详情替换列表；仅在宿主能保证三栏可读宽度时使用 `data-layout="wide"` |
| 项目 | `data-knowledge-item`、稳定的 `data-knowledge-value`、`data-knowledge-phase` 与 `aria-selected` |
| 阶段 | `ready`、`queued`、`running`、`succeeded`、`failed`、`paused` |
| 方法 | `select`、`clearSelection`、`getSelection`、`setFilter`、`clearFilter`、`getFilter`、`setPhase`、`runAction`、`setState`、`refresh`、`getState` |
| 授权事件 | `a3s:knowledge-before-action`、`a3s:knowledge-before-filter-change`、`a3s:knowledge-before-selection-change` |
| 观察事件 | `a3s:knowledge-action`、`a3s:knowledge-filter-change`、`a3s:knowledge-selection-change`、`a3s:knowledge-phase-change`、`a3s:knowledge-state-change` |
| 根状态 | `ready`、`loading`、`empty`、`partial`、`error`、`offline`、`permission-denied` |

## 无障碍与所有权

知识库条目保持为列表中的具名按钮；方向键、Home 和 End 在可见条目间移动，Enter 或空格打开详情。状态必须同时包含文字，不能只依靠颜色。详情中的同级视图使用 Tabs 契约。宿主负责授权、摄取任务、重试、来源校验、存储、检索、删除恢复与用户内容本地化。
