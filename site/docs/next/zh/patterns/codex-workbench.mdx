## 组合结构

```text
App Shell
├── Activity Bar：项目与线程
└── 主工作区
    ├── Workspace Header：线程与环境标识
    ├── Split Pane
    │   ├── Agent Transcript + Agent Composer
    │   │   └── Execution Item / Approval Request
    │   └── Task Pane：上下文与线程元数据
    └── Status Bar
```

该模式不引入新的公共根类或产品状态，直接使用各组件已记录的 API。项目选择、线程历史、流式传输、Git 状态、审批和持久化仍归宿主应用所有。预览中的名称、路径、数量和执行结果均为示例数据。

## 响应式行为

- 低于 768px 时，把项目导航转换为 App Shell 的局部抽屉。
- 在对话区域过窄前，把检查器转换为 Task Pane 浮层行为或 Drawer。
- 在 DOM 顺序中把 Agent Composer 放在 Transcript 之后，并固定在可见对话区域底部。
- 先隐藏低优先级元数据，保留主要执行状态和操作。

## 无障碍

为项目导航、对话、分割线、检查器和状态地标命名。当前项目或线程使用 `aria-current`。阻塞型审批到达时，只有应用确实无法继续才移动焦点；其他情况播报到达并保留读者位置。不要把整个 Transcript 设为一个连续 Live Region。
