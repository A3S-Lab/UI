# Color

The A3S palette uses cool neutral surfaces and one deliberately scarce blue. Green, amber, and red report semantic state; they do not become page themes or category branding.

## Semantic tokens

| Role | Light | Dark | Use |
| --- | --- | --- | --- |
| `--background` | `#f8f9fb` | `#101118` | Application canvas |
| `--foreground` | `#17191d` | `#f2f3f5` | Primary content |
| `--card` | `#ffffff` | `#171820` | Raised or grouped surfaces |
| `--muted` | `#f1f3f6` | `#1e2028` | Subtle fills and controls |
| `--muted-foreground` | `#667085` | `#a4a8b2` | Supporting text |
| `--border` | `#e6e8ec` | `#2a2d35` | Dividers and boundaries |
| `--primary` | `#2864e8` | `#6ca3ff` | Primary actions and selection |
| `--ring` | `#2864e8` | `#6ca3ff` | Keyboard focus |
| `--destructive` | `#c9363c` | `#f27777` | Destructive actions and errors |

Use blue for action, selection, progress, and focus. Use green, amber, and red only when status requires them; none of these colors should fill a whole navigation or page region. Text still needs sufficient contrast in both themes.

```css
.my-resource {
  --resource-accent: var(--a3s-blue);
}
```

## Parameters

Theme switching uses the `dark` class on `<html>`. Consumers can override any semantic token at `:root`, within `.dark`, or inside a scoped product container. Keep the token names stable so components and documentation previews stay synchronized.
