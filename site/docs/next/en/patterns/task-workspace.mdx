# Task Workspace

Task Workspace combines durable task navigation, a chronological work record, planning, execution evidence, review, a bottom composer, and an optional context inspector. Applications keep transport, repository, scheduling, persistence, and policy logic.

## Composition

```text
App Shell
├── Activity Bar: destinations, recent tasks, and projects
└── Task Workspace
    ├── Workspace Header
    ├── Task Transcript
    │   ├── Message Status, Attachment, and Citation
    │   ├── Task Plan + Plan Step
    │   ├── Tool Call, Execution Item, and Approval Request
    │   └── Terminal, Execution Evidence, Artifact Card, and Follow-up Suggestions
    ├── Agent Composer
    └── Task Pane
        ├── Context Selector
        ├── Task Queue
        ├── Checkpoint
        └── Change Review
```

Task history, plan transitions, execution transport, permission enforcement, approvals, file changes, evidence retention, and persistence stay in the host application. Names, paths, counts, and results in the preview are illustrative data.

## Responsive behavior

- Below 768px, App Shell navigation becomes a contained drawer and leaves the layout while closed.
- Below 900px, the inspector leaves the grid and opens as a Task Pane overlay.
- Below 520px, the inspector opens from the bottom and the composer keeps safe-area spacing.
- Transcript, composer, and inspector keep their DOM order. Long tool, terminal, queue, and change content scrolls inside its declared owner.

## Accessibility

Name task navigation, transcript, inspector, context controls, and composer. Mark the current destination and plan step. Return focus after closing navigation or inspector overlays. Announce bounded message, execution, approval, queue, and checkpoint changes; do not make the entire transcript or terminal stream live.
