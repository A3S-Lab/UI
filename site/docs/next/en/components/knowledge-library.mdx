# Knowledge Library

Knowledge Library manages durable source collections, indexing state, search, pinned libraries, recovery, and per-library settings without pretending that a visual component owns ingestion, embeddings, storage, or permissions.

## Product decisions

A knowledge base is a durable, named boundary around approved sources. It is not a folder alias, a chat attachment list, or a decorative database card.

- Every library exposes source count, freshness, indexing phase, and a recovery path.
- `queued` and `running` are distinct because waiting for capacity and actively indexing require different expectations.
- A failed update preserves the last usable searchable version. Destructive rebuilds require an explicit host flow.
- Automatic updates need a stated policy, minimum interval, pause behavior, and a visible manual recovery action.
- Source selection, authentication, parsing, chunking, embeddings, vector storage, retrieval quality, and access control remain host responsibilities.

`useKnowledgeLibrary` exposes the same controller methods and DOM events to React and Vue. Application data remains in the host store; the hook does not duplicate indexing state.

## Controller contract

| Area | Contract |
| --- | --- |
| Root | `.knowledge-library`, preferably a `<section>` |
| Layout | The default keeps navigation and replaces the list with an open detail view; use `data-layout="wide"` only when the host guarantees room for three readable panes |
| Items | `data-knowledge-item`, stable `data-knowledge-value`, `data-knowledge-phase`, and `aria-selected` |
| Phases | `ready`, `queued`, `running`, `succeeded`, `failed`, `paused` |
| Methods | `select`, `clearSelection`, `getSelection`, `setFilter`, `clearFilter`, `getFilter`, `setPhase`, `runAction`, `setState`, `refresh`, `getState` |
| Authorization | `a3s:knowledge-before-action`, `a3s:knowledge-before-filter-change`, `a3s:knowledge-before-selection-change` |
| Observation | `a3s:knowledge-action`, `a3s:knowledge-filter-change`, `a3s:knowledge-selection-change`, `a3s:knowledge-phase-change`, `a3s:knowledge-state-change` |
| Root states | `ready`, `loading`, `empty`, `partial`, `error`, `offline`, `permission-denied` |

## Accessibility and ownership

Library items remain ordinary named buttons in a list; arrow keys, Home, and End move between visible items while Enter or Space opens details. Status always includes text and never depends on color. Detail tabs, when present, use the Tabs contract. The host owns authorization, ingestion jobs, retries, source validation, storage, retrieval, deletion recovery, and localized user data.
