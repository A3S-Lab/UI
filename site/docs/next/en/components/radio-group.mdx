# Radio Group

Radio Group presents a short set of mutually exclusive options. Use it when every option can be understood without opening another surface and choosing one value is required to continue or configure the current task.

## Usage

Import Tailwind and the complete A3S style bundle:

```css
@import "tailwindcss";
@import "@a3s-lab/ui/a3s.css";
```

Give related native radio inputs the same `name`. Associate every input with a visible label, then give the complete group one accessible name through `fieldset` and `legend` or `role="radiogroup"` and `aria-labelledby`.

```html
<fieldset class="fieldset">
  <legend data-variant="label">View density</legend>
  <div class="grid gap-3">
    <div class="field" data-orientation="horizontal">
      <input
        class="input"
        type="radio"
        id="density-default"
        name="density"
        value="default"
      />
      <label for="density-default">Default</label>
    </div>
    <div class="field" data-orientation="horizontal">
      <input
        class="input"
        type="radio"
        id="density-compact"
        name="density"
        value="compact"
        checked
      />
      <label for="density-compact">Compact</label>
    </div>
  </div>
</fieldset>
```

For component-level loading, import the base styles, Radio structure, Field structure, and the A3S visual style in that order. See [Installation](/installation) for CDN and other integrations.

```css
@import "@a3s-lab/ui/base.css";
@import "@a3s-lab/ui/components/radio.css";
@import "@a3s-lab/ui/components/field.css";
@import "@a3s-lab/ui/styles/a3s.css";
```

### Parameters

| Parameter          | Value                               | Purpose                                                                      |
| ------------------ | ----------------------------------- | ---------------------------------------------------------------------------- |
| Group              | `<fieldset>` or `role="radiogroup"` | Gives the related choices one semantic boundary and name                     |
| Root class         | `radio-group`                       | Applies the stable group layout and framework-adapter contract               |
| Root option        | `<input type="radio">`              | Preserves native form, validation, keyboard, and accessibility behavior      |
| `class`            | `input`                             | Applies Radio structure and visual styles                                    |
| `name`             | Shared string                       | Makes the options mutually exclusive and submits one value                   |
| `value`            | Stable string                       | Provides the submitted application value; do not derive it from visible copy |
| `checked`          | Boolean attribute                   | Marks the actual initial selection; omit it when the user must make a choice |
| `disabled`         | Boolean attribute                   | Prevents selection; explain why the option is unavailable                    |
| `required`         | Boolean attribute                   | Requires one option in the named native group before form submission         |
| `aria-invalid`     | `true`                              | Exposes a failed validation state after validation has run                   |
| `aria-describedby` | Element ID                          | Associates constraints, consequences, or recovery guidance                   |

## States and variants

Unchecked and checked are the normal interactive states. Arrow keys move selection inside the focused native group; Tab enters and leaves the group as a single stop. Disabled and invalid appearances are meaningful only when the surrounding content explains the constraint or recovery.

### Invalid

Do not mark a valid preselected value as an error. Start without an error, validate only after an attempted continuation, focus the first option when the group is still empty, and clear stale error semantics as soon as the user recovers or resets the form.

## React

`RadioGroup` renders the manifest root. `useRadioGroup` listens to the bubbling native `change` event; the application still owns the selected value and form submission.

```tsx
import { useState } from "react";
import { RadioGroup, useRadioGroup } from "@a3s-lab/ui/react";

export function DensitySetting() {
  const [density, setDensity] = useState("comfortable");
  const group = useRadioGroup({
    events: {
      change(event) {
        const option = event.target as HTMLInputElement;
        if (option.type === "radio" && option.checked) setDensity(option.value);
      },
    },
  });

  return (
    <RadioGroup
      ref={group.ref}
      aria-labelledby="density-label"
      className="w-fit"
    >
      <span id="density-label" className="label">
        View density
      </span>
      {[
        ["default", "Default"],
        ["comfortable", "Comfortable"],
        ["compact", "Compact"],
      ].map(([value, label]) => (
        <div className="field" data-orientation="horizontal" key={value}>
          <input
            className="input"
            type="radio"
            id={`density-${value}`}
            name="density"
            value={value}
            defaultChecked={value === density}
          />
          <label htmlFor={`density-${value}`}>{label}</label>
        </div>
      ))}
      <output>Current density: {density}</output>
    </RadioGroup>
  );
}
```

## Vue

The Vue composable subscribes to the same native event. Its template ref connects the semantic group while reactive state remains application-owned.

```vue
<script setup lang="ts">
import { ref } from "vue";
import { RadioGroup, useRadioGroup } from "@a3s-lab/ui/vue";

const density = ref("comfortable");
const group = useRadioGroup({
  events: {
    change(event) {
      const option = event.target as HTMLInputElement;
      if (option.type === "radio" && option.checked)
        density.value = option.value;
    },
  },
});
const componentRef = group.componentRef;
const options = [
  ["default", "Default"],
  ["comfortable", "Comfortable"],
  ["compact", "Compact"],
];
</script>

<template>
  <RadioGroup ref="componentRef" aria-labelledby="density-label" class="w-fit">
    <span id="density-label" class="label">View density</span>
    <div
      v-for="[value, label] in options"
      :key="value"
      class="field"
      data-orientation="horizontal"
    >
      <input
        class="input"
        type="radio"
        :id="`density-${value}`"
        name="density"
        :value="value"
        :checked="value === density"
      />
      <label :for="`density-${value}`">{{ label }}</label>
    </div>
    <output>Current density: {{ density }}</output>
  </RadioGroup>
</template>
```

## Accessibility

- Give the complete group one concise accessible name. Prefer `fieldset` and `legend` in forms; otherwise use `role="radiogroup"` with `aria-labelledby` or `aria-label`.
- Give every radio a visible `label` and one stable submitted `value`. A description belongs in `aria-describedby`, not inside an excessively long accessible name.
- Use one shared `name` for mutually exclusive options. Do not simulate exclusivity with independent buttons or application-only state.
- Keep native arrow-key behavior. Tab enters the selected radio, arrows move and select, and Tab leaves the group; do not create a separate Tab stop for every option.
- Do not add `role="group"` to every option row. The radiogroup or fieldset is the only group boundary.
- Set `disabled` on only the unavailable option and keep its reason visible. If all choices are unavailable, disable the owning form action and explain the blocking condition.
- Show an invalid state only after validation runs. Use `required`, `aria-invalid="true"`, and `aria-describedby` to connect a recovery-oriented error; clear stale error attributes and text when a valid option is chosen or the form is reset.
- Keep the full radio hit target at least 44px on coarse pointers even though the visible indicator remains compact.
