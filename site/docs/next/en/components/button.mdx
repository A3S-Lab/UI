# Button

Buttons trigger actions in the current interface. Use a link with `href`, styled as a button, when the outcome is navigation.

## Usage

Import Tailwind and the complete A3S style bundle:

```css
@import "tailwindcss";
@import "@a3s-lab/ui/a3s.css";
```

Then add the `btn` class to a native button. Set `type="button"` explicitly so a button does not submit a form by accident.

```html
<button type="button" class="btn">Save changes</button>
```

For component-level loading, import the base styles, Button structure, and A3S visual style in that order. See [Installation](/installation) for CDN and other integration paths.

```css
@import "@a3s-lab/ui/base.css";
@import "@a3s-lab/ui/components/button.css";
@import "@a3s-lab/ui/styles/a3s.css";
```

### Parameters

| Parameter      | Values                                                               | Purpose                                              |
| -------------- | -------------------------------------------------------------------- | ---------------------------------------------------- |
| Root element   | `<button>` or `<a>`                                                  | Use a button for actions and a link for navigation   |
| `class`        | `btn`                                                                | Required component root class                        |
| `data-variant` | `primary`, `secondary`, `outline`, `ghost`, `link`, `destructive`    | Sets action hierarchy; omission means primary        |
| `data-size`    | `xs`, `sm`, `default`, `lg`, `icon-xs`, `icon-sm`, `icon`, `icon-lg` | Sets target size and visual density                  |
| `data-icon`    | `inline-start` or `inline-end`                                       | Place on inline icons to correct text-button spacing |
| Native state   | `disabled`, `aria-busy`, `aria-pressed`                              | Expresses unavailable, pending, and toggle states    |

Button has no JavaScript controller or dedicated framework hook. HTML, React, and Vue use the same native activation and state attributes; application state owns the asynchronous operation and its duplicate-submission guard.

## States and variants

Keep one primary button in a decision region. Use `secondary` and `outline` for supporting actions, `ghost` for low-emphasis tools, and `destructive` only when the action has a clear destructive outcome. `link` is a visual variant; real navigation still uses `<a href>`.

## Accessibility

- Use `<button>` for actions and `<a href>` for navigation. Do not imitate links with click handlers.
- Every icon-only button needs an accessible name, usually through `aria-label`.
- Keep a specific action label visible during loading, synchronize `disabled` with `aria-busy="true"`, and set the duplicate-submission guard before awaiting host work.
- Application state owns `aria-pressed="true|false"` for toggles. Buttons that reveal overlays use `aria-expanded` and `aria-controls`.
- A destructive button communicates intent. When confirmation is required, pair it with [Alert Dialog](/components/alert-dialog).
- The A3S style pack provides one visible offset focus outline without a box-shadow halo. Do not remove it in application styles.
