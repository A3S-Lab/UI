# Checkbox

Checkbox lets people select zero, one, or several non-exclusive options. Use it for choices that are submitted with a form; use [Switch](/components/switch) for a binary setting that takes effect immediately.

## Usage

Import Tailwind and the complete A3S style bundle:

```css
@import "tailwindcss";
@import "@a3s-lab/ui/a3s.css";
```

Add the `input` class to a native checkbox and associate it with a `label`. A single input can pair directly with its label.

```html
<div class="field" data-orientation="horizontal">
  <input class="input" type="checkbox" id="include-logs" name="include-logs" />
  <label for="include-logs">Include diagnostic logs</label>
</div>
```

For component-level loading, import the base styles, Checkbox structure, Field structure, and the A3S visual style in that order. See [Installation](/installation) for CDN and other integrations.

```css
@import "@a3s-lab/ui/base.css";
@import "@a3s-lab/ui/components/checkbox.css";
@import "@a3s-lab/ui/components/field.css";
@import "@a3s-lab/ui/styles/a3s.css";
```

### Parameters

| Parameter | Value | Purpose |
| --- | --- | --- |
| Root | `<input type="checkbox">` | Preserves native form, keyboard, and accessibility semantics |
| `class` | `input` | Applies Checkbox structure and visual styles |
| `checked` | Boolean attribute | Marks the option selected; on server-rendered pages, use it only for the real default |
| `disabled` | Boolean attribute | Prevents interaction; also add `data-disabled` to the owning `.field` |
| `aria-invalid` | `true` | Exposes a failed validation state |
| `aria-describedby` | Element ID | Associates help, constraints, or error text |
| `indeterminate` | DOM property | Indicates partial child selection; it is not a third submitted value |

## States and variants

Unchecked and checked are the normal interactive states. Disabled choices must explain why they are unavailable. Show invalid state only after submission or field departure so the page does not open with premature errors.

`indeterminate` is a DOM property commonly used by a “select all” control. Form submission still follows `checked`, so applications must maintain both values explicitly.

```js
const selectAll = document.querySelector("#select-all");
const selectedCount = 2;
const totalCount = 5;

selectAll.checked = selectedCount === totalCount;
selectAll.indeterminate = selectedCount > 0 && selectedCount < totalCount;
```

Row selection inside a table belongs to the complete interaction model of [Table](/components/table) or [Data Grid](/components/data-grid). Its “select all” control must synchronize visible rows, cross-page scope, and indeterminate state; do not present an inert table gallery in Checkbox documentation.

## React

`Checkbox` renders the native input declared by the manifest. `useCheckbox` can connect `change` and `input` DOM events to application state, but it does not own the selected value.

```tsx
import { useState } from "react";
import { Checkbox, useCheckbox } from "@a3s-lab/ui/react";

export function ReleaseNotification() {
  const [enabled, setEnabled] = useState(false);
  const checkbox = useCheckbox({
    events: {
      change(event) {
        setEnabled((event.currentTarget as HTMLInputElement).checked);
      },
    },
  });

  return (
    <div className="field" data-orientation="horizontal">
      <Checkbox ref={checkbox.ref} id="release-notification" name="release-notification" />
      <section>
        <label htmlFor="release-notification">Release notifications</label>
        <p aria-live="polite">{enabled ? "Enabled" : "Not enabled"}</p>
      </section>
    </div>
  );
}
```

## Vue

The Vue composable subscribes to the same manifest event. The template ref connects the native input, while reactive state remains application-owned.

```vue
<script setup lang="ts">
import { ref } from "vue";
import { Checkbox, useCheckbox } from "@a3s-lab/ui/vue";

const enabled = ref(false);
const checkbox = useCheckbox({
  events: {
    change(event) {
      enabled.value = (event.currentTarget as HTMLInputElement).checked;
    },
  },
});
const componentRef = checkbox.componentRef;
</script>

<template>
  <div class="field" data-orientation="horizontal">
    <Checkbox ref="componentRef" id="release-notification" name="release-notification" />
    <section>
      <label for="release-notification">Release notifications</label>
      <p aria-live="polite">{{ enabled ? "Enabled" : "Not enabled" }}</p>
    </section>
  </div>
</template>
```

## Accessibility

- Every checkbox needs an accessible name, preferably a visible `label` paired through `id`.
- Group related options with `fieldset` and `legend`; do not add redundant `role="group"` to an ordinary `.field`.
- Space toggles a focused native checkbox. Do not replace browser behavior with a custom click handler or block label activation.
- Associate help and error copy with `aria-describedby`; set `aria-invalid="true"` when validation fails.
- Keep the label and unavailability reason visible for disabled options. If users still need to understand or copy the content, disable only the control rather than hiding the row.
- `indeterminate` communicates partial selection visually and semantically; form submission still follows `checked`.
