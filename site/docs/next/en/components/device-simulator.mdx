# Device Simulator

Device Simulator switches between phone, tablet, and desktop viewports inside a bounded workbench and renders the matching hardware shell for each class. Browser mode uses a real-size `iframe`; native mode hands safe arguments to a trusted host that can launch `a3s-webview`.

The phone shell includes a metal rail, sensor area, and bottom gesture region, while the tablet shell includes a narrow bezel and camera. Laptops add a display bezel, hinge, and base; desktop monitors add a chin and stand. Every shell scales with its device to fit the workbench, while the iframe retains the exact selected CSS viewport dimensions.

The simulator does not spoof the User-Agent, device pixel ratio, or touch capability, inject safe-area variables into the target, or simulate network throttling or operating-system browser behavior. The target must also allow iframe embedding; pages restricted by `X-Frame-Options` or CSP `frame-ancestors` should use native preview instead.

### Parameters

| Parameter                                 | Values                       | Default                   | Purpose                                                     |
| ----------------------------------------- | ---------------------------- | ------------------------- | ----------------------------------------------------------- |
| Preset `data-width`                       | `240`–`4000`                 | —                         | Preset CSS viewport width                                   |
| Preset `data-height`                      | `180`–`3000`                 | —                         | Preset CSS viewport height                                  |
| Preset `data-kind`                        | `phone`, `tablet`, `desktop` | Inferred from width       | Selects the phone, tablet, or computer hardware shell       |
| Preset `data-orientation`                 | `portrait`, `landscape`      | Keeps current orientation | Synchronizes a preset's natural orientation when selected   |
| Root `data-orientation`                   | `portrait`, `landscape`      | `portrait`                | Current screen orientation                                  |
| Root `data-fit`                           | `actual` or omitted          | Automatic fit             | Uses a 1:1 scale or shrinks the viewport into the workspace |
| Root `data-device-title`                  | String                       | iframe title              | Native window title                                         |
| `--device-simulator-workspace-min-height` | CSS length                   | `38rem`                   | Workspace minimum height                                    |
| `--device-simulator-workspace-max-height` | CSS length                   | `44rem`                   | Workspace maximum height                                    |

Custom dimensions are clamped to the same range as `a3s-webview`. Changing either custom input selects the option whose value is `custom` and emits a size-change event.

### JavaScript API

The root element exposes these methods after initialization:

| Method                   | Purpose                                                                |
| ------------------------ | ---------------------------------------------------------------------- |
| `setDevice(value)`       | Selects a preset and returns `false` when it does not exist            |
| `setSize(width, height)` | Switches to custom dimensions and clamps the values                    |
| `setOrientation(value)`  | Sets `portrait` or `landscape`                                         |
| `navigate(url?)`         | Validates and opens an HTTP, HTTPS, file, or relative URL              |
| `refreshPreview()`       | Reloads the current iframe URL                                         |
| `openNativePreview()`    | Emits a native preview request, then copies the command when unhandled |

Dimension changes emit `a3s:device-change`; URL navigation emits `a3s:device-navigate`. Native preview uses the cancelable, bubbling, and composed `a3s:device-preview-request` event. Its `detail` contains `{ executable, args, url, width, height, title, command }`.

A trusted host should call `preventDefault()` to claim the request and use the structured `args` directly. Do not reparse the display-and-copy-only `command` string.

```js
const simulator = document.querySelector(".device-simulator");

simulator.addEventListener("a3s:device-preview-request", async (event) => {
  if (!window.trustedPreviewHost) return;
  event.preventDefault();

  const { executable, args } = event.detail;
  await window.trustedPreviewHost.launch({ executable, args });
});
```

The web controller never executes a local process directly. Without a trusted host, Native preview only copies the equivalent command to the clipboard.

## States and variants

- `data-state="loading"` exposes progress while the iframe navigates.
- `data-state="ready"` means the dimensions or preview are synchronized.
- `data-state="error"` reports an invalid URL or copy failure and names the recovery in the status output.
- Phones, tablets, laptops, and desktop monitors use distinct bezels, sensors, bases, or stands. The iframe always uses the real CSS-pixel dimensions in the controls.
- A `file:` URL can be handed to a native host. Browser security policy decides whether an iframe may load a local file.

## Accessibility

Give the root, preset selector, orientation group, URL input, and iframe accessible names. Orientation buttons use `aria-pressed`, and status output uses `aria-live="polite"`. The workspace remains an independent scroll owner, and scaling the visual frame does not reorder keyboard focus inside the iframe. Custom dimension controls must retain numeric `min`, `max`, and clear labels.

## React

```tsx
import { DeviceSimulator, useDeviceSimulator } from "@a3s-lab/ui/react";

export function Example() {
  const control = useDeviceSimulator();
  return (
    <DeviceSimulator ref={control.ref} aria-label="Device Simulator">
      Component content
    </DeviceSimulator>
  );
}
```

`useDeviceSimulator` subscribes to manifest-declared DOM events and calls only public manifest methods. The adapter creates no second, framework-only state model.
