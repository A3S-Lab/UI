# App Page

App Page provides an open, width-bounded page frame for projects, automations, catalogs, forms, and detail views inside App Shell. It keeps page identity and actions stable without adding a card around the whole view.

## Usage

```html
<section class="app-page" data-width="wide">
  <header>
    <div data-page-identity><h1>Projects</h1><p>Durable work context.</p></div>
    <div data-page-actions>...</div>
  </header>
  <div data-page-content>...</div>
</section>
```

### Parameters

| API | Values | Purpose |
| --- | --- | --- |
| `class="app-page"` | required | Open application page frame |
| `data-page-identity` | required | Heading and concise description |
| `data-page-actions` | optional | Page-level primary and secondary actions |
| `data-page-content` | required | Page-owned content |
| `data-width` | `reading`, `wide`, omitted | Content measure |

## States and variants

Use child Empty, Skeleton, Alert, Resource Card, Table, or form components for empty, loading, error, partial-data, and permission states. Do not add another generic page card.

## Accessibility

Use the heading level appropriate to the surrounding document. Keep actions after the identity in DOM order and preserve that order when the header stacks on narrow screens.

## React

```tsx
import { AppPage } from "@a3s-lab/ui/react";

export function Example() {
  return (
    <AppPage aria-label="App Page">Component content</AppPage>
  );
}
```

The adapter replaces only the documented semantic root and adds no wrapper; its children keep the HTML contract shown above.
