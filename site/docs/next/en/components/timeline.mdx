## Usage

Import the full style bundle, or compose Timeline with the components used by each entry.

```css
@import "tailwindcss";
@import "@a3s-lab/ui/a3s.css";
```

```html
<ol class="timeline" aria-label="Execution history">
  <li data-state="success">
    <article class="item" data-variant="outline">…</article>
  </li>
  <li data-state="active" aria-current="step">
    <article class="item" data-variant="outline">…</article>
  </li>
</ol>
```

### Parameters

| API                   | Values                                   | Purpose                                                   |
| --------------------- | ---------------------------------------- | --------------------------------------------------------- |
| `class="timeline"`    | Required                                 | Ordered timeline root                                     |
| `data-marker`         | Short text or number                     | Replaces the dot with a compact marker                    |
| `data-state`          | `active`, `success`, `warning`, `danger` | Semantic marker color                                     |
| `aria-current="step"` | Native ARIA                              | Identifies the current step and uses the active treatment |

## States and variants

Map domain statuses to the four semantic states in the host application. Do not expose every backend status as a styling API. Omit `data-state` for neutral or future events, and use text or a Badge so color is never the only status signal.

## Accessibility

Use `<ol>` when order matters and `<time datetime="…">` for timestamps. Keep the current state explicit with `aria-current="step"`. Timeline is CSS-only; focus, selection, and live announcements remain the host application's responsibility.
