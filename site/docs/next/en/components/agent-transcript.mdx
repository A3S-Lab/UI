# Agent Transcript

Agent Transcript presents user, agent, and system Turns in chronological DOM order. It accepts streamed content without owning transport, Markdown rendering, history retention, or virtualization.

## Usage

```html
<section class="agent-transcript" aria-label="Conversation">
  <ol data-transcript-viewport tabindex="0">
    <li data-role="user"><article>...</article></li>
    <li data-role="agent"><article>...</article></li>
    <li data-role="system"><article>...</article></li>
  </ol>
</section>
```

### Parameters

| API                                         | Values                      | Purpose                                                   |
| ------------------------------------------- | --------------------------- | --------------------------------------------------------- |
| `class="agent-transcript"`                  | Required                    | Named conversation region                                 |
| Direct `<ol>` or `data-transcript-viewport` | Recommended                 | Ordered, bounded Turn viewport                            |
| Child `data-role`                           | `user`, `agent`, `system`   | Stable presentation role, independent of provider names   |
| Child `<article>`                           | Recommended                 | One message or Turn surface                               |
| `data-message-content`                      | Recommended                 | Rich text, code, execution items, approvals, and evidence |
| `data-transcript-status`                    | Optional                    | Coarse asynchronous status                                |
| `--agent-transcript-content-width`          | CSS length, default `47.5rem` | Maximum reading-column width                            |
| `--agent-transcript-gap`                    | CSS length, default `1rem`    | Gap between Turns                                       |
| `--agent-message-max-width`                 | CSS length, default `48rem`   | Readable message width                                  |

## States and variants

Assistant output remains open document content on the canvas; user Turns use the restrained blue authored surface, and system notices use a bounded notice. Execution, approval, citation, and artifact blocks stay inside the owning Turn without adding a border around the whole assistant response. Loading, empty, interrupted, and failed histories should remain explicit content, using Empty or Alert when appropriate. During streaming, append or update the active Agent Turn without rebuilding earlier Turns. Window long histories in the host application while preserving the logical ordered-list position with `aria-posinset` and `aria-setsize` when known.

## Accessibility

Give the region an accessible name and preserve chronological DOM order. Make only an actually overflowing viewport focusable. Announce coarse state such as “Agent finished” or “Approval required”; do not place the token stream itself in a live region. New content must not steal focus or force the page to scroll when the reader has moved away from the latest Turn.
