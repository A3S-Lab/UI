# Form system

A3S UI's structured-form components keep schemas, visual design, controlled rendering, validation, and workflow-node configuration on one deterministic contract. They use the same A3S UI visual language as buttons, fields, data grids, and application shells. Examples live directly in the component guides; there is no separate product site or form demo route.

## Choose an integration layer

| Layer | Entry point | Use it for |
| --- | --- | --- |
| Form Core | `@a3s-lab/ui/form/core` | Compilation, rules, validation, patches, locale, and headless state |
| React components | `@a3s-lab/ui/form/react` | Designer, Renderer, Flow panels, and extended fields |
| React hooks | `@a3s-lab/ui/form/react-hooks` | React Hook Form resolver, subscriptions, field arrays, and Renderer binding |
| Vue components | `@a3s-lab/ui/form/vue` | Vue 3 Designer and Renderer adapters |
| Vue composables | `@a3s-lab/ui/form/vue-hooks` | Form, field, field-array, context, validation, and submission state |
| Web Components | `@a3s-lab/ui/form/web-component` | Framework-neutral Designer and Renderer custom elements |
| Workflow | `@a3s-lab/ui/form/workflow` | Workflow configuration, protected submissions, and interaction digests |

```bash
npm install @a3s-lab/ui
```

React applications install `react`, `react-dom`, and `react-hook-form` when needed. Vue applications install `vue`. Both framework surfaces share one Form Core instead of producing a second schema or validation contract.

## Current component capabilities

- 23 built-in fields plus matrix, repeater, data-grid, file-upload, and signature extensions;
- grid, column, card, tab, collapsible-content, and branched-wizard layouts;
- deterministic computed rules, host-owned async validation, dynamic data sources, and locale catalogs;
- A3S Form Schema Profile 1 and native Rust/WASM submitted-value evaluation;
- 18 visible A3S Flow 1.0 DAG manifests with lossless validation and semantic digests;
- controlled React, Vue, and Web Component adapters with shared read-only, error, locale, and host-capability boundaries.

## Product boundary

The components own document compilation, controlled values, interaction, and inspectable change. Persistence, identity, permission, credentials, file storage, network requests, business side effects, and final submission remain host-owned.
