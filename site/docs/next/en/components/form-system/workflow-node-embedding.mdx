# A3S Flow 1.0 DAG node configuration

A3S Form treats the Flow workflow DSL as a lossless DAG contract. Flow owns graph structure, scope validation, execution ordering, and semantic digests. The integrating host owns every `node.data.type`, its property manifest, node-specific compilation, credentials, persistence, and execution.

## Contract baseline

| Contract | Implemented baseline |
| --- | --- |
| A3S Flow engine | `1.0.0` |
| Tested workflow DSL | `0.7.0` |
| Primary manifest catalog | 18 visible nodes and 2 internal container-start nodes |
| Runtime commands | 14 Flow 1.0 command bindings |
| Component system | `@a3s-lab/ui@0.3.0` |
| Form compatibility | `a3s-flow/1.0.0`, `a3s-flow-workflow-dsl/0.7.0` |

The primary Playground groups the 18 visible manifests into Control flow, Task execution, Wait & callbacks, Run outcome, Run control, Child work, and Containers. `iteration-start` and `loop-start` are created inside their owning container and stay out of the insertion catalog.

## Ownership boundary

| Flow-owned contract | Host-owned contract |
| --- | --- |
| Lossless `nodes`, `edges`, scopes, and unknown presentation extensions | The meaning of each `data.type` discriminator |
| Node and edge limits, stable IDs, references, acyclic ordering, and cross-scope edge rejection | Property fields, labels, defaults, ports, and host-specific node manifests |
| Iteration and loop container/start-node invariants | Compilation from a manifest-backed DAG node to Flow commands or host operations |
| Canonical execution digest with presentation-only fields removed | Handler registries, credentials, authorization, persistence, and side effects |

Form does not rewrite unknown DAG fields. Configuration edits replace only fields declared by the selected manifest, retain `data.type`, and preserve every top-level authoring or presentation extension.

## Host-owned manifests

`A3SFlowDagNodeManifest` is the single source of truth for a node's configuration surface. A host can use the built-in catalog or register product-specific types without expanding the Flow engine protocol.

```ts
import {
  createA3SFlowDagNodeRegistry,
  defineA3SFlowDagNodeManifest,
} from '@a3s-lab/ui/form/a3s-flow';

const approvalManifest = defineA3SFlowDagNodeManifest({
  type: 'acme.approval',
  display_name: 'Approval',
  description: 'Wait for a decision owned by the host.',
  category: 'host',
  categoryLabel: 'Host nodes',
  role: 'host',
  ports: {
    inputs: [{ id: 'in', label: 'In', kind: 'control', types: ['FlowControl'] }],
    outputs: [{ id: 'approved', label: 'Approved', kind: 'control', types: ['FlowControl'] }],
  },
  input_types: ['FlowState'],
  output_types: ['FlowState'],
  fields: [
    {
      name: 'team',
      display_name: 'Review team',
      type: 'str',
      _input_type: 'StrInput',
      value: 'finance',
      required: true,
    },
  ],
  outputs: [],
});

export const flowNodeRegistry = createA3SFlowDagNodeRegistry([approvalManifest]);
```

Registry creation rejects duplicate types. Manifest construction rejects empty identifiers, duplicate field names, runtime-command nodes without a binding, and containers without a start-node contract.

## React embedding

```tsx
import { useState } from 'react';
import {
  createA3SFlowDagNode,
  requireA3SFlowDagNodeManifest,
} from '@a3s-lab/ui/form/a3s-flow';
import {
  A3SFlowDagNodeConfigurationPanel,
  A3SFlowDagNodePreview,
} from '@a3s-lab/ui/form/react';
import '@a3s-lab/ui/form/a3s-ui.css';

const manifest = requireA3SFlowDagNodeManifest('flow.step');

export function StepSettings() {
  const [dagNode, setDagNode] = useState(() =>
    createA3SFlowDagNode('step-fetch-customer', manifest),
  );

  return (
    <div className="node-settings">
      <A3SFlowDagNodePreview dagNode={dagNode} manifest={manifest} />
      <A3SFlowDagNodeConfigurationPanel
        dagNode={dagNode}
        manifest={manifest}
        onChange={setDagNode}
        connectedOutputPortIds={connectedOutputPortIds}
        onApply={(nextNode, document) =>
          saveDagNode({
            node: nextNode,
            formCompatibility: document.metadata.compatibility,
          })
        }
        onRequestConnection={({ valuePath, inputTypes }) =>
          openConnectionPicker({ valuePath, inputTypes })
        }
      />
    </div>
  );
}
```

The panel is controlled and host-neutral. It never resolves edges, saves data, loads credentials, or executes a node. Missing manifests render a localized alert and leave the DAG node untouched. Expression, input-schema, and batch fields use their structured editors on this main path; applicable core-node semantic checks run before the host-level Form validator and block Apply on failure.

If the host already loads A3S UI, use the scoped entries instead:

```ts
import '@a3s-lab/ui/form/styles.css';
import '@a3s-lab/ui/form/a3s-flow.css';
```

## DAG validation and semantic digest

```ts
import {
  compileA3SFlowWorkflowDag,
  digestA3SFlowWorkflowDag,
  parseA3SFlowWorkflowDslJson,
} from '@a3s-lab/ui/form/a3s-flow';

const parsed = parseA3SFlowWorkflowDslJson(source);
if (!parsed.ok) throw new Error(parsed.issues[0]?.message);

const graph = parsed.document.workflow.graph;
const compilation = compileA3SFlowWorkflowDag(graph);
if (!compilation.ok) throw new Error(compilation.issues[0]?.message);

const executionDigest = digestA3SFlowWorkflowDag(graph);
```

The parser enforces the 10 MiB document limit and classifies DSL-version compatibility. DAG compilation enforces the 10,000-node and 100,000-edge bounds, unique IDs, valid endpoints and parents, same-scope edges, acyclic order, and valid iteration/loop start children. The digest sorts nodes and edges by UTF-8 ID and removes viewport, selection, position, size, animation, style, and other presentation-only fields. Renaming the app or moving a node therefore does not change execution identity; semantic graph changes do.

## Primary panel properties

| Property | Type | Required | Purpose |
| --- | --- | --- | --- |
| `dagNode` | `A3SFlowWorkflowDagNode` | Yes | Complete lossless DAG node controlled by the host |
| `manifest` | `A3SFlowDagNodeManifest` | No | Explicit manifest; otherwise resolved from `registry` by `data.type` |
| `registry` | `A3SFlowDagNodeRegistry` | No | Host registry; defaults to the built-in Flow 1.0 catalog |
| `onChange` | `(node) => void` | Yes | Receives a node with manifest-owned fields merged losslessly |
| `onApply` | `(node, document) => void \| Promise<void>` | No | Commits the current node through the host |
| `onReset` | `(node) => void` | No | Observes reset to manifest defaults |
| `connectedOutputPortIds` | `readonly string[]` | No | Supplies graph context for conditional-port validation |
| `onRequestConnection` | `(request) => void` | No | Opens a host connection picker |
| `hostAdapter` | `FormHostAdapter` | No | Resolves approved data sources, validation, and actions |
| `widgetRegistry` | `FormWidgetRegistry` | No | Adds or overrides approved controls |
| `locale` | `string` | No | Selects runtime copy and formatting |
| `readOnly` | `boolean` | No | Disables reset, editing, connection, and Apply actions |

`A3SFlowDagNodePreview` accepts the same `dagNode`, optional `manifest` or `registry`, and graph presentation options such as `selected`, `technical`, and `className`. It renders manifest ports and the runtime binding but does not own graph selection or edge state.

## Migration compatibility

`A3SFlowNodeConfigurationPanel`, `A3SFlowNodePreview`, `A3SFlowCoreNodeDefinition`, and the eight-node `0.4.2` catalog remain available only for migrations. Their individual [legacy node chapters](/components/form-system/a3s-flow/start) document the old value-only contract. New editors should store an `A3SFlowWorkflowDagNode` and use the DAG panel and preview.

The pinned Langflow `1.11.3` descriptor adapter is a separate import compatibility layer, not a Flow node catalog. See [Langflow compatibility](/components/form-system/langflow-compatibility).
