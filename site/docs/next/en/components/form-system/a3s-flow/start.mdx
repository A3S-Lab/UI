# Workflow Start

> [!IMPORTANT]
> This page documents the eight-node A3S Flow `0.4.2` compatibility API for migration only. New editors should use the [Flow 1.0 DAG-node contract](/components/form-system/workflow-node-embedding) and `A3SFlowDagNodeConfigurationPanel`.

`flow.start` sets the workflow identity, runtime entrypoint, input schema, and optional run ID used to start a workflow run.

<A3SFlowNodeDemo nodeType="flow.start" />

## Developer contract

| Contract | Value |
| --- | --- |
| Category | Control flow |
| Runtime binding | `workflow_input` |
| A3S Flow version | `0.4.2` |
| Stable command ID | Not applicable |
| Lowering | Host calls `start` or `start_with_id` |

## Use in MDX

Pass the stable node type to embed the Workflow Start configuration example:

```mdx

<A3SFlowNodeDemo nodeType="flow.start" />
```

## Configuration properties

| Property | Value type | Required | Default | Notes |
| --- | --- | --- | --- | --- |
| `workflow_name` | `string` | Yes | `workflow.main` | Stable identifier stored in `WorkflowSpec`. |
| `workflow_version` | `string` | Yes | `0.1.0` | Immutable version used when a saved workflow resumes. |
| `runtime_kind` | `native_ts \| rust_embedded` | Yes | `native_ts` | Rendered as a compact tab control. |
| `entrypoint` | `string` | Yes | `workflows/main.ts` | Runtime source path or embedded runtime key. |
| `export_name` | `string` | Yes | `main` | Exported workflow function. |
| `input_schema` | JSON object | Yes | `{ "type": "object", "additionalProperties": true }` | JSON Schema accepted by the host at start time. |
| `run_id_expression` | Flow expression | No | Literal `null` | Advanced. A non-null value selects idempotent `start_with_id`. |

## Ports

Workflow Start has no input ports.

| Direction | ID | Label | Kind | Types | Availability |
| --- | --- | --- | --- | --- | --- |
| Output | `next` | Next | Control | `FlowControl` | Always |
| Output | `input` | Workflow input | Data | `JsonValue` | Always |

## Configuration value

```json
{
  "workflow_name": "records.review",
  "workflow_version": "0.1.0",
  "runtime_kind": "native_ts",
  "entrypoint": "workflows/records-review.ts",
  "export_name": "main",
  "input_schema": {
    "type": "object",
    "properties": {
      "requestId": { "type": "string" },
      "recordId": { "type": "string" }
    },
    "required": ["requestId", "recordId"],
    "additionalProperties": false
  },
  "run_id_expression": {
    "apiVersion": "a3s.dev/flow-expression/v1",
    "expression": { "op": "field", "path": "input.requestId" }
  }
}
```

## Validation and runtime contract

- Form validation checks required strings and JSON object shapes.
- Node validation checks the expression envelope and supported AST operators.
- A non-null run-ID expression must reference at least one field. Node-local validation does not restrict the field-path namespace.
- The integrating system validates input against `input_schema`, restricts run-ID paths to workflow input or saved state, and resolves the runtime entrypoint.
- A null run-ID expression uses `start`; a non-null expression uses `start_with_id` after host resolution.
