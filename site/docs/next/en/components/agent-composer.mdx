# Agent Composer

Agent Composer captures the next instruction, attached context, queued input, and send or stop actions. The host application owns uploads, shortcuts, submission, cancellation, and queue persistence.

## Usage

```html
<form class="agent-composer" aria-label="Message the coding agent">
  <ul data-composer-context aria-label="Attached context">
    ...
  </ul>
  <textarea name="prompt" aria-label="Instruction"></textarea>
  <footer>
    <div data-composer-tools>...</div>
    <div data-composer-actions>
      <button type="submit" class="btn">Send</button>
    </div>
  </footer>
</form>
```

### Parameters

| API                           | Values                                                           | Purpose                                                     |
| ----------------------------- | ---------------------------------------------------------------- | ----------------------------------------------------------- |
| `class="agent-composer"`      | Required                                                         | Standalone `<form>`, or a Section inside an owning Form     |
| `data-state`                  | `idle`, `submitting`, `streaming`, `queued`, `error`, `disabled` | Finite presentation state owned by the host                 |
| `data-composer-context`       | Optional list                                                    | Attachments, files, symbols, source ranges, images, or URLs |
| `data-composer-tools`         | Optional container                                               | Attachment and context controls                             |
| `data-composer-actions`       | Recommended container                                            | Send, queue, stop, or retry actions                         |
| `data-composer-status`        | Optional status text                                             | Submission or queue feedback                                |
| `data-composer-queue`         | Optional ordered list                                            | Messages waiting behind an active Turn                      |
| `--agent-composer-min-height` | CSS length, default `5.5rem`                                     | Minimum textarea height                                     |
| `--agent-composer-max-height` | CSS length, default `18rem`                                      | Maximum textarea height before internal scrolling           |

## States and variants

Use native `disabled` on individual controls and `aria-disabled="true"` only when the entire composer is unavailable. Keep input text when submission fails. During streaming, applications may send immediately, queue the message, or disable submission; the button label and status text must state which behavior applies.

Attachments and queue items are application data. A3S UI neither uploads files nor mutates a queue. Native `submit` and button events are the integration points. Use a `<section class="agent-composer">` only when an ancestor Form already owns the submit boundary; nested Forms are invalid.

## Accessibility

Give the form and textarea accessible names. Keep each removal button adjacent to the item it removes and include the item name in the button label. Put asynchronous status copy in a polite live region, but do not announce every streamed token. Preserve ordinary IME composition and multiline textarea behavior; product shortcuts must not intercept Enter while composition is active.

## React

```tsx
import { AgentComposer, useAgentComposer } from "@a3s-lab/ui/react";

export function Example() {
  const control = useAgentComposer();
  return (
    <AgentComposer ref={control.ref} aria-label="Agent Composer"><label>Name<input name="name" /></label><button type="submit">Continue</button></AgentComposer>
  );
}
```

`useAgentComposer` subscribes to manifest-declared DOM events and calls only public manifest methods. The adapter creates no second, framework-only state model.
