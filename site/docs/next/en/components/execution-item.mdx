# Execution Item

Execution Item is a native disclosure for one command, tool call, edit, search, browser action, or MCP invocation. It keeps the integration contract stable while applications supply domain-specific details.

## Usage

```html
<details class="execution-item" data-state="running">
  <summary>
    <span data-execution-icon aria-hidden="true">...</span>
    <span data-execution-identity
      ><strong>Run tests</strong><small>npm test</small></span
    >
    <span data-execution-status>Running</span>
    <span data-execution-disclosure aria-hidden="true">...</span>
  </summary>
  <section>...</section>
  <footer>...</footer>
</details>
```

### Parameters

| API                         | Values                                                          | Purpose                                                    |
| --------------------------- | --------------------------------------------------------------- | ---------------------------------------------------------- |
| `class="execution-item"`    | Required on `<details>`                                         | Native disclosure root                                     |
| `data-state`                | `queued`, `running`, `waiting`, `success`, `error`, `cancelled` | Provider-neutral execution state                           |
| `data-execution-icon`       | Optional                                                        | Tool-kind icon, decorative when the title names the action |
| `data-execution-identity`   | Required                                                        | Action title and compact target or command                 |
| `data-execution-status`     | Recommended                                                     | Textual status, normally a Status Badge                    |
| `data-execution-disclosure` | Optional                                                        | Directional disclosure icon                                |
| Direct `<section>`          | Optional                                                        | Parameters, output, patch, evidence, or error details      |
| Direct `<footer>`           | Optional                                                        | Stop, retry, inspect, or copy actions                      |

## States and variants

Map backend-specific states into the six public states and retain detailed wording in `data-execution-status`. Use `waiting` for approval or external input. Keep partial output visible after error or cancellation. Nested Execution Items are allowed only when the parent represents a real delegated group; avoid deep disclosure trees.

## Accessibility

Native `<details>` and `<summary>` provide disclosure semantics and keyboard behavior. The visible title must identify the action without relying on its icon. Do not put the Summary inside a button. Keep output in ordinary text or `<pre>` unless records are genuinely live; use Log Viewer for high-volume streams.

## React

```tsx
import { ExecutionItem, useExecutionItem } from "@a3s-lab/ui/react";

export function Example() {
  const control = useExecutionItem();
  return (
    <ExecutionItem ref={control.ref}><summary>View details</summary><div>Component content</div></ExecutionItem>
  );
}
```

`useExecutionItem` subscribes to manifest-declared DOM events and calls only public manifest methods. The adapter creates no second, framework-only state model.
