# Tool Call

Tool Call is a native disclosure for one named integration invocation. It separates structured input from structured output while keeping provider details optional.

## Usage

```html
<details class="tool-call" data-state="success">
  <summary><span data-tool-identity><strong>Read repository status</strong><small>shell</small></span><span data-tool-status>Success</span></summary>
  <section><pre data-tool-input>...</pre><pre data-tool-output>...</pre></section>
</details>
```

### Parameters

| API | Values | Purpose |
| --- | --- | --- |
| Root `<details>` | Required | Native disclosure behavior |
| `data-state` | `queued`, `running`, `waiting`, `success`, `cancelled`, `error` | Invocation state |
| `data-tool-input` | Optional | Structured parameters |
| `data-tool-output` | Optional | Structured result or error |

## States and variants

Use Tool Call when input/output structure matters. Use Execution Item for a higher-level action and Terminal for continuous command output.

## Accessibility

The visible title names the action without relying on the provider or icon. Redact secrets before rendering input or output.
